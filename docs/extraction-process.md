# 文本提取与更新流程

本文只记录适合公开归档的流程边界，不提供资源保护密钥、私有元数据偏移、具体工具或
完整解密实现。完整研究材料应保存在仓库之外的本地开发缓存中。

## 输入边界

输入来自维护者依法取得并保存在本地的游戏安装包、资源缓存与文本资源。所有原始输入
均不得复制到本仓库。

## 处理阶段

1. 在隔离的本地开发目录保存当前版本输入，并记录版本与文件指纹。
2. 从资源清单中定位语言文本相关资源，区分名称、界面文本和技能描述表。
3. 在本地还原资源容器并解析其序列化格式。
4. 将每张表规范化为“表名 → 语言 → 文本 ID → 字符串”的 JSON 结构。
5. 保留原始文本标记、空字符串、换行与语言集合，不进行翻译或语义改写。
6. 在临时目录完成结构、条目数、哈希与禁止内容检查。
7. 只把三份审核通过的 JSON 和更新后的 `manifest.json` 写入本仓库。

## 版本更新

游戏更新后应建立新的临时快照，不直接覆盖已发布数据。比较新旧文本键和内容变化，重点
检查异常大规模删除、语言缺失、编码损坏以及顶层结构变化。确认差异合理后再替换：

```text
data/texts/extracted/cardnametext.json
data/texts/extracted/cardtext.json
data/texts/extracted/skilldesctext.json
```

随后更新 `manifest.json` 中的快照日期、字节数、SHA-256、语言列表和条目数，并按
[`verification.md`](verification.md) 完成发布前检查。

## 禁止进入仓库的中间产物

- 安装包、原生库、AssetBundle 和解密后的资源容器
- 数据库、主数据全表、卡图和模拟器画面
- 反编译源码、符号转储、运行日志和临时报告
- 解包脚本、第三方工具、依赖目录和下载压缩包
- 本机绝对路径、账号信息、访问令牌、资源保护密钥及私有偏移

根目录 `.gitignore` 使用白名单规则作为最后一道保护，但更新者仍须在提交前人工检查
完整文件列表。
